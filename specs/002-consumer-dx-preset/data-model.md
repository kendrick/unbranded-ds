# Phase 1 Data Model: Consumer DX preset

This feature has no persistent data model in the traditional sense — there is no database, no API entities, no migrations. The "model" here is the set of artifacts and their relationships that compose the public API surface of the two affected packages.

## Entities

### E1 — `tokens/preset.css` (file)

**Path**: `packages/tokens/dist/tailwind/preset.css` (existing, content unchanged in this spec)

**Reachable from consumer via**: `@import '@unbranded-ds/tokens/preset.css'` (new clean alias added in this spec)

**Content contract**: a single Tailwind v4 `@theme inline` block mapping every token name to a `var(--token-name)` reference. Registration-only — never sets default values. Spec FR-005 enforces this; FR-001/FR-002 require the clean alias.

**Relationships**:
- Imported by E2 (the React preset)
- Imported directly by tokens-only consumers (Vue, Svelte, vanilla HTML)
- Generated by Style Dictionary from the DTCG sources under `packages/tokens/src/tokens/`

### E2 — `react/preset.css` (file)

**Path**: `packages/react/dist/preset.css` (new in this spec)

**Source**: `packages/react/src/preset.css` (hand-authored, two-line file)

**Reachable from consumer via**: `@import '@unbranded-ds/react/preset.css'` (new clean alias)

**Content contract**: exactly two directives:
```css
@import '@unbranded-ds/tokens/preset.css';
@source "../@unbranded-ds/react";
```

The `@source` path is relative to the file's location in `node_modules/@unbranded-ds/react/dist/`, resolving to `node_modules/@unbranded-ds/react` — which is what Tailwind needs to scan for component class names.

**Relationships**:
- Wraps E1 (tokens preset)
- Built artifact; sourced from `src/preset.css` via the tsup `onSuccess` hook
- Imported by Tailwind+React consumers as the canonical wiring

### E3 — `themeBootstrapScript` (string constant)

**Path**: `packages/tokens/src/runtime.ts` (added in this spec)

**Reachable from consumer via**: `import { themeBootstrapScript } from '@unbranded-ds/tokens/runtime'`

**Type**: `string`

**Shape**: a stringified self-executing function that reads `localStorage.getItem('unbranded-ds-theme')`, falls back to `'light'` on missing or blocked storage, and sets `data-theme` on the document root before first paint. Wrapped in try/catch for blocked-storage safety.

**Equivalence**: `themeBootstrapScript === getThemeBootstrapScript()` (called with no arguments, default `'light'`).

**Relationships**:
- Equivalent to E4 with the default argument
- Shares the private localStorage-key constant with E4 (single source of truth — no drift)
- Consumed by JSX as `<script dangerouslySetInnerHTML={{ __html: themeBootstrapScript }} />`
- Consumed by HTML templates as a literal `<script>{themeBootstrapScript}</script>` injection

### E4 — `getThemeBootstrapScript` (factory function)

**Path**: `packages/tokens/src/runtime.ts` (added in this spec)

**Reachable from consumer via**: `import { getThemeBootstrapScript } from '@unbranded-ds/tokens/runtime'`

**Type**:
```ts
function getThemeBootstrapScript(options?: { defaultTheme?: string }): string
```

**Shape**: accepts an optional `{ defaultTheme }` parameter (default value `'light'`) and returns a string with the same structure as E3 but with the supplied `defaultTheme` substituted as the fallback.

**Determinism**: output is byte-identical across builds for the same argument value (verified per FR-014). No closures, no environment-dependent values, no randomness.

**Relationships**:
- E3 is `getThemeBootstrapScript()` evaluated at module load time
- Output is consumed identically to E3 (inlined as the body of a `<script>` element)

### E5 — `unbranded-ds-theme` (localStorage key constant)

**Path**: `packages/tokens/src/runtime.ts` (module-private constant, not exported in this spec)

**Reachable from consumer via**: not directly. Encoded into the strings emitted by E3 and E4.

**Type**: `string`, value `'unbranded-ds-theme'`

**Shape**: a single fixed string literal. Project memory (`project_ds_theme_localstorage_key`) names this as the canonical key for theme persistence across the design system; FR-006 specifies the value.

**Relationships**:
- Interpolated into E3 and E4 outputs
- Will be re-read by `useTheme()` in spec 007 — that spec must import the same constant to avoid drift
- Candidate for public export in spec 007 (so the `useTheme` hook can import from a single source)

### E6 — `<VisuallyHidden>` (React component)

**Path**: `packages/react/src/components/VisuallyHidden/VisuallyHidden.tsx` (new in this spec)

**Reachable from consumer via**: `import { VisuallyHidden } from '@unbranded-ds/react'`

**Type** (simplified):
```ts
type VisuallyHiddenProps<T extends keyof JSX.IntrinsicElements = "span"> = {
  as?: T
  children?: React.ReactNode
  className?: string
} & Omit<React.ComponentPropsWithoutRef<T>, "as" | "children" | "className">

function VisuallyHidden<T extends keyof JSX.IntrinsicElements = "span">(
  props: VisuallyHiddenProps<T>
): React.ReactElement
```

**Shape**: a polymorphic React component that renders its children inside an element of type `as` (default `"span"`) with the `.sr-only` Tailwind utility applied. Forwards all other props through. The class is `cn("sr-only", className)` so consumers can extend with their own classes if needed.

**Relationships**:
- Re-exported from `packages/react/src/index.ts`
- Uses `cn()` from `@unbranded-ds/react/src/lib/cn` (existing utility)
- Uses Tailwind's built-in `.sr-only` utility (no custom CSS)
- Ships with stories, tests, and autodocs per constitution Sections V, VI, IX

## Validation rules (across entities)

Captured from spec FRs and clarifications:

- The two preset.css files MUST keep `@theme inline` registration-only (FR-005). Inlining default theme values into a preset.css file would force the upstream's defaults onto every consumer and break consumer overrides. Verified by: a build-time lint or test that scans each preset.css for token-value-looking declarations.
- E3 and E4 MUST agree on the localStorage key (E5 is the single source). Verified by: a unit test asserting both outputs contain the same `'unbranded-ds-theme'` literal.
- E4 output MUST be deterministic. Verified by: a unit test calling the factory twice and asserting byte-equality (plus SHA-256 equality for the CSP hash contract).
- E6 MUST NOT redefine `.sr-only` (FR-008). Verified by: a lint rule or test confirming no CSS in the React package declares `.sr-only`.

## State transitions

There are no state transitions in this feature. The bootstrap script runs once on page load and sets `data-theme`. The `<VisuallyHidden>` component is stateless. The CSS files are static.

The theme value in `localStorage` does change over time (when a user toggles their preference), but mutating `localStorage` is the consumer's responsibility — the bootstrap script only reads. Mutation lives in spec 007's `useTheme` hook.
